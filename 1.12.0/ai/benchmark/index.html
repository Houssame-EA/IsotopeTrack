    benchmark.py¶

    Score a model on questions with known answers.

    The assistant can only be improved if "better" is measured. This module generates synthetic datasets whose truth is known (see :mod:results.ai.synthetic), asks a model a fixed set of questions through the same pipeline the chat window uses (code, sandbox, correction, grounded takeaway) and checks every answer automatically.

    The question set is built from 36 templates (counts, statistics, yes/no reasoning and figures) asked on three datasets with different samples, sizes, a contamination burst and an alloy population planted in different places. Datasets rivers and wastewater form the dev split; lakes is the test split and should never be used to make training examples, so a model trained on the others is still measured on data it has not seen.

    Figures are checked on what was actually drawn: axis scales, number of panels, series, points or bars, axis labels and titles where asked for, reference lines, colour maps, and the drawing warnings the chat shows the model (empty panels, missing axis labels, overlapping text).

    On top of those, each dataset has:

    • custom: single requests for detailed figure customisation (a second y-axis, points above a threshold in another colour, a colour scale for a third quantity, error bars, axis range and grid, a fixed colour for one sample, an annotation with an arrow, marker shape and legend placement);
    • table: one table covering every element in every sample, checked value by value;
    • edit: conversations of three requests where each one changes the previous figure; every step must keep what was asked before and add the new change, which tests whether the model edits its own code instead of starting over;
    • explore: open and targeted explorations run through the same loop as the Explore button, scored on how many of the planted features the summary reports (the Ce:La ratio shift, the non-natural Pb isotope ratio, the Ag+Au alloy sample, the sample with larger Ti, the Fe burst for the iron question) and failed on a false discovery (Ti+Fe called a real association).

    Every question goes through the same steps as the chat window: up to three code corrections, one figure redraw when the drawing checks complain, and the grounded takeaway, with the history kept the way the chat keeps it.

    Run it from the repository root against a local model::

    python -m results.ai.benchmark --backend ollama --model qwen3.8:27b-mlx
python -m results.ai.benchmark --backend mlx --host http://127.0.0.1:8080
python -m results.ai.benchmark --reference

    Thinking is off by default, as in the app; --think switches it on.

    --reference answers with the built-in reference code instead of a model, which checks the benchmark itself. --split, --dataset, --category and --only select part of the set. Results print per question with a summary per category and split, and can be saved as JSON with --out.

    Classes¶

    Question¶

    One benchmark question.

    Attributes: qid (str): Identifier, dataset.template. text (str): The question as a user would ask it. kind (str): number, text or figure. expected: Number, regular expression or figure requirement. tolerance (float): Relative tolerance for numbers. reference (str): Code that answers it correctly, for --reference. reject (str): Regular expression that must not match the answer. first_of (dict): Name to regular expression; when set, expected must be the first of these names the answer mentions. reference_answer (str): The takeaway the reference model gives. dataset (str): Dataset key. split (str): dev or test. category (str): One of :data:CATEGORIES. steps (list): For conversation questions, one dict per request with text, req (what the figure must show after that request, counting everything asked so far) and reference. findings (dict): For explore questions, name to (patterns, unless): one sentence of the summary must match every pattern and not unless for the feature to count. forbidden (dict): Claims that fail an explore question, in the same form as findings. need (int): Findings required to pass an explore question. max_turns (int): Exploration turn budget.

    Outcome¶

    How one question went.

    Attributes: qid (str): Question id. dataset (str): Dataset key. split (str): dev or test. category (str): Question category. passed (bool): Whether the answer was right. attempts (int): Code runs needed. fixes (int): Corrections and figure redraws the model was asked for. seconds (float): Wall time. error (str): Last sandbox or backend error. detail (str): Why it passed or failed. answer (str): The final answer text. transcript (list): The whole conversation with the model, code included, so a failure can be read afterwards.
